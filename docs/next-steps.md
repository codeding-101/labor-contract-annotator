## 下一步：把文件格式补全（这是最硬的一块）

PDF 的文本层已经接上（`pdfjs-dist`，浏览器端，按需加载），坐标重组行的逻辑在引擎的 `src/text-lines.ts`（纯函数、有单测）。接新格式时的分工已经定好：**「文件 → 文本行」放在 `web/`，其余交给引擎**。

按价值与难度排序：

| 格式 | 难度 | 做法 |
|---|---|---|
| `.docx` | 低 | mammoth 在浏览器里可用，产出 HTML → 复用 `htmlToBlocks` |
| `.doc`（Word 97-2003） | 中 | `word-extractor` 已在 Node 侧接入并能读出正文，但**段落边界不可靠**（实测把「注意事项」六条连成一行）；浏览器端要验证它能否打包运行 |
| 图片 / 扫描件 | **高** | 浏览器端没有可靠又免费的中文 OCR。诚实的做法是「尽力识别 + 用户核对修正」并明示准确率较低；不要用低准确率结果直接出报告 |
| 直接粘贴 / PDF 文本层 | 已完成 | — |

**图片这条路要单独立项想清楚**：它是真实场景里最常见的一种（学生拿到纸质合同拍照），但也是本地化架构下最难的一种。可选的折中：先做「上传图片 → 显示图片 → 用户照着录入或粘贴条款」，把工具做成录入辅助，而不是假装能自动识别。

## 下一步：发布（只差你建仓推送）

部署已经全部就绪，只等远端仓库：

- `.github/workflows/deploy-web.yml`：推到 `main` 自动构建并发布；**它先跑 `npm run check`**（构建数据 + 全部断言与评测），挂了就不部署，顺带兼任质量闸门。
- `web/vite.config.ts` 设了 `base: './'`——项目站点在 `/<仓库名>/` 下，绝对路径会全部 404。这一点在本地把 `web/dist` 挂到子路径下实测过：界面、CSS、PDF 的按需分块与 worker 都正常。
- `web/public/.nojekyll` 让 Pages 跳过 Jekyll。

需要你做的三步（仓库目前只有本地 git，也没装 `gh` CLI，所以只能你来）：新建空仓库 → `git remote add origin …` 并 `git push -u origin main` → Settings → Pages 里把 Source 选成 "GitHub Actions"。地址将是 `https://<用户名>.github.io/<仓库名>/`。

**推送后把活链接补进 README 的顶部**——作品集项目里，一个能点开的链接比多十个功能都值钱。

## 案例语料：继续收（需要人工找材料）

企业劳动合同不公开，所以拿公开案例当真实措辞的来源。管线已跑通：`sources/cases.json` 声明 → `sources/cases/<file>` 快照 → `npm run build:cases` → `data/cases/*.json`。

**新收案例后的标准动作**：先拿它去撞现有规则，看有没有漏报——真实措辞的价值主要在这里，而不是数量。已经因此修掉三处（社保的「不为…缴纳」写法、社保义务「转嫁给个人承担」、中文数字「两」），并新增了一整类规则。发现漏报要补通用那一层，不要为单个措辞加特例。

**抓取注意**：国内政务网站**必须绕过系统代理**——本机 Clash 是全局模式，会把国内站点也绕到境外出口，政务网站对境外 IP 常直接 403（实测同一 URL：经代理 403、直连 200）。做法见 `AGENTS.md`。

工具现状：`web_search` 在本机不可用（原因见 `AGENTS.md`），`web_fetch` 可用但同样受代理影响。所以需要人工找到案例页面 URL 再交给我抓取。**优先找这几类**：

- 人社部与各级人社厅发布的「劳动人事争议典型案例」「违法用工典型案例」

## 一处需要留意的设计约定

法条与范本库里**只放能追溯到官方原文的内容**，规则库里的每条规则都必须绑定真实存在的法条 ID（`statuteRefs`），追溯不到的规则不写；规则里也不复制法条原文，报告要展示哪条就按 ID 从法条库取哪条。

这不是洁癖——作者不是法学专业，这条约束是把「个人法律判断」从系统里彻底移除的唯一办法。改这块代码时请保持这个约束。
