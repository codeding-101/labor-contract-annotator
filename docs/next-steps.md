## 下一步：评分与报告组装

引擎的三块输出已经齐了——差异清单（`diffAgainstTemplate`）、风险项与无法判定项（`evaluateRules`）、事实（`extractFacts`）——但还没有把它们组装成"用户会看到的那份报告"。这是动界面之前最后一层。

建议动作：

1. 定义报告的数据结构（`src/build-report.ts`）：综合评分、风险计数、差异清单、15 项关键信息、三段总结（工资／工时／社保福利）、签署建议。
2. **评分要透明可解释，不要黑盒。** 用红黄蓝加权计数、并给出算式；命中的高危项做一票封顶。报告里明说"分数由差异与规则命中算出，不代表法律评价"。
3. **无法判定的项要单独成块**，不能混进"合规"里。这是事实层那条约束在报告层的延续——用户需要知道"这条我没能判断"，而不是以为已经查过了。
4. 15 项关键信息的表格大多可以直接由事实层 + 差异清单拼出来；拼不出的（如"发薪日期"）需要补事实键。

做完这一层，再进应用界面（纯前端网页 → 单文件下载）。

## 案例语料：继续收（需要人工找材料）

企业劳动合同不公开，所以拿公开案例当真实措辞的来源。管线已跑通：`sources/cases.json` 声明 → `sources/cases/<file>` 快照 → `npm run build:cases` → `data/cases/*.json`（案例序号、标题、基本案情、裁判结果、典型意义）。

**新收案例后的标准动作**：先拿它去撞现有规则，看有没有漏报——真实措辞的价值主要在这里，而不是数量。已经因此修掉两处（社保的「不为…缴纳」写法、中文数字「两」）。发现漏报要补通用那一层，不要为单个措辞加特例。

**抓取注意**：国内政务网站**必须绕过系统代理**——本机 Clash 是全局模式，会把国内站点也绕到境外出口，政务网站对境外 IP 常直接 403（实测同一 URL：经代理 403、直连 200）。做法见 `AGENTS.md`（`HttpWebRequest` + `Proxy = $null`，落原始字节）。

工具现状：`web_search` 在本机不可用（原因见 `AGENTS.md`），`web_fetch` 也可用但同样受代理影响。所以需要人工找到案例页面 URL 再交给我抓取。**优先找这几类**：

- 人社部与各级人社厅发布的「劳动人事争议典型案例」「违法用工典型案例」
- 最高人民法院及地方法院发布的劳动争议典型案例
- 与《劳动争议司法解释（二）》配套的案例集

## 真实合同接入（技术前提未定）

用户在界面里给的是 PDF / Word / 图片。合同侧需要比 `extract-template.ts` 更宽容的抽取器：真实合同不保证有「一、」节标题、也不保证条号连续，识别失败时要能退化成"段落即条款"，而不是直接报错。PDF 文本层与 `.docx` 读取器都还没接。

## 范本覆盖度（待补）

目前只有 1 份：湖北省鄂州市梁子湖区的《劳动合同（通用）》，正文以 HTML 内联发布，所以管线走 HTML 分支。

要扩到更多地区，需要处理 **Word 97-2003 二进制 `.doc`**——实测北京、上海、广东、河南、沈阳、浙江、福州的官方范本基本都是 `.doc` 附件，网页正文里没有条款内容。纯 JS 读取器 `word-extractor` 已接入（`src/read-doc.ts`），能读出正文，**但它对段落边界的还原不可靠**（实测某市范本把"注意事项"六条连成了一行）。接入 `.doc` 范本前必须先验证段落边界。`.docx` 需要另加读取器（mammoth），尚未接。

## 一处需要留意的设计约定

法条与范本库里**只放能追溯到官方原文的内容**，规则库里的每条规则都必须绑定真实存在的法条 ID（`statuteRefs`），追溯不到的规则不写；规则里也不复制法条原文，报告要展示哪条就按 ID 从法条库取哪条。

这不是洁癖——作者不是法学专业，这条约束是把"个人法律判断"从系统里彻底移除的唯一办法。改这块代码时请保持这个约束。
